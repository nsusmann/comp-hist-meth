How I used Codex to agentically code this site

Dr. Natalie M. Susmann

As a Digital Archaeologist who teaches computational research methods to Humanists and Social Scientists, I believe in maintaining transparency in how I use AI to create research and teaching materials. This site was developed in Codex using OpenAI's GPT-5.6-sol model. The linked transcript includes the user-visible prompts and responses from the development conversation. Here's an overview of how I made this website, and precisely where I used agentic coding:

  1. I brainstormed and wrote the contents of this lesson in a Google doc, which is linked on the main page as a PDF.
  2. I assembled all of the contents for the examples. These include: that Google doc (which I offered as a Markdown file), my project datasets, the sources to data tutorial (which I created), etc.1
  3. I gave Codex permission to create a page on my GitHub.
  4. I had this conversation with Codex. Notice how I began by giving no guidance on the aesthetics. Codex built out the site and I could see a demo version. I disliked how Codex transformed my writing into a graphic-forward interface, because (in my opinion) it gave the impression of an overly-AI design. I gave it more direction, explaining it should be more clearly drawing from the format of my original PDF.

The whole contents of this site are mine, and I understand the core framework in how it was created. I am able to communicate with Codex and understand decisions about the programming language, APIs, etc. Agentic coding makes it easier for me to create useful educational tools and digital examples for my students.

1. I've integrated agentic coding into portions of the analyses and data presented on this site. For example, I used Claude to create the text analysis interface, including the data cleanup and analytical stages. I gave Claude commands about how to clean the original dataset of reviews: standardizing place names and abbreviations, removing extraneous punctuation, etc. Based on my decades of experience working with digital textual data, I knew how the data should look, and prompting Claude to actually make the changes really sped up the process. I designed the framework of the text analysis: all of the categories and subcategories, as well as the defining terms for each. Claude coded all of the text (i.e., assigned reviews to certain categories and subcategories) according to those definitions. For each of these results, I read through samples and provided Claude with corrections; this process was repeated until suitable accuracy was retained. These accuracy scores are shown in the text analysis interface. Similar to how I used Codex to create this website, I prompted Claude to create an interface for me easily reference these results, which I prefer over a traditional database (e.g., an Excel sheet).
